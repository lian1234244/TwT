# Mineradio 自适应性能优化方案

## 目标与边界

- 低配和核显设备首先保证按钮、滚动、拖动、控制台显隐和切歌响应。
- 不默认删除粒子、玻璃、歌词呼吸、动态壁纸或 3D 歌单架。
- 降载必须渐进、可恢复、有滞回，避免画质在两个档位间来回跳动。
- 用户手动指定的帧率和画质仍是上限；自动策略不能擅自突破上限。

## 当前结论

项目已经具备帧率选择、像素预算、后台休眠、交互期 QoS、节奏分析 Worker、列表分批渲染和运行时快照。主要缺口不是缺少某个动画库，而是这些能力还没有统一成一个根据真实帧耗时闭环调节的调度器。

当前 `getRenderLoadTier()` 主要根据窗口与渲染像素判断负载。1080p 弱核显可能被判为低负载，而高分辨率高性能显卡反而会被提前限流。现有 FPS/长帧统计也尚未参与画质反馈。

## 推荐架构：统一自适应视觉调度器

### 1. 先消除不可见工作

- 每个视觉子系统声明 `active`、`priority`、`updateRate` 和 `dirty`。
- 非当前预设的歌词画布、粒子层、3D 歌单架、Home 波形和背景深度任务不进入每帧更新。
- 静止、暂停、最小化和无变化场景改为按需渲染；播放中的主歌词和进度仍保持连续更新。
- 视觉控制台、队列拖动、搜索滚动期间暂停低优先级缓存整理与深度生成。

这一阶段不改变画面，只减少无效 CPU/GPU 工作，应作为第一优先级。

### 2. 用实测帧耗时闭环调节

建立 `AdaptivePerformanceController`，每 2 秒读取：

- 实际 FPS、P95 帧耗时、长帧比例；
- Three.js draw calls、三角形、纹理数和内部像素数；
- 当前是否为视频背景、3D 歌单架、粒子、歌词或 UI 交互；
- 可选的 GPU 初始档位，仅作为冷启动提示。

连续 3 个采样窗超预算才降一级，连续 8 个采样窗稳定才升一级。这样能够适应弱核显、节能模式、发热降频和后台负载，而不会频繁闪变。

### 3. 保真降载顺序

从最不易被察觉的项目开始：

1. 降低非焦点系统的更新频率，例如歌单架惯性、Home 波形、背景深度和远景粒子。
2. UI 操作期间冻结不可见预设、缓存整理和次级装饰动画。
3. 视频背景的取帧频率与主歌词帧率解耦；视频可 30/40 FPS，歌词与控制栏仍跟随显示器。
4. 持续超预算时，以 0.05 为步长微调内部像素比，最低值受当前画质档保护。
5. 最后才降低远景粒子密度、后处理采样或玻璃更新频率；不直接关闭效果。

恢复顺序反向执行，并使用更长稳定窗口，防止反复波动。

### 4. 主线程减负

- 保留现有节奏分析 Worker。
- 图像裁剪、封面深度采样、粒子源图预处理等 CPU 工作按性能记录逐项迁移到 Worker/OffscreenCanvas。
- 不一次性迁移 Three.js 主渲染，不优先改 WebGPU；这两项兼容和回归成本高。
- 避免引入大型框架重写 `public/index.html`，先把调度和采样拆成独立模块。

## 可借鉴的开源方法

- `@pmndrs/detect-gpu`：可作为首次启动的 GPU 档位提示，但不能作为唯一依据。
- Three.js 按需渲染与像素预算：用于空闲、暂停和高 DPI 场景。
- Electron Performance 指南：以实测、延迟加载、Worker 和非阻塞操作为核心。

建议借鉴方法而不直接引入完整运行时依赖。Mineradio 已有自己的质量档和渲染循环，复用其策略比套入 React/Three.js 生态组件更稳。

## 实施阶段与验收

### 阶段 A：零视觉损失

- 统一子系统 active/dirty 调度。
- 修复无效的每帧调用和重复 DOM/样式写入。
- 建立可导出的性能基线报告。

验收：相同画面截图一致；播放、滚动和控制台操作的 P95 帧耗时下降；无新增功能回归。

### 阶段 B：自适应控制器

- 接通运行时采样、滞回状态机和动态像素比。
- 增加“自动优化”详情，展示当前瓶颈与采取的降载项目。

验收：1080p 核显设备在动态壁纸加粒子场景中交互无明显卡顿；画质切换不可见或仅在持续高负载时轻微发生。

### 阶段 C：热点任务离线程

- 以性能记录为依据迁移封面处理、深度图和次级 Canvas。
- 不迁移没有被证明是瓶颈的任务。

验收：主线程长任务数量和切歌后歌词同步延迟进一步下降。

## 推荐测试矩阵

- 1080p/60Hz 核显商务本、2K/60Hz 中端独显、4K/120Hz 高端设备。
- 静态背景、视频背景、Wallpaper 转换背景。
- 粒子加歌词、3D 歌单架侧栏、3D 歌单架舞台、DIY 控制台拖动。
- 播放、切歌、搜索滚动、队列拖动、最小化恢复和窗口缩放。

每个场景记录平均 FPS、P95 帧耗时、长帧比例、draw calls、内部像素数、内存和输入响应延迟。

## 2026-07-16 实施状态

- 阶段 A 已接入显式视觉任务掩码，仅调度当前活跃的 Home、歌词预设、歌单架、骷髅、粒子歌词和桌面叠加层。
- 已移除主循环中无实际工作的 `updateFloatLayer()` 每帧调用。
- 阶段 B 已接入只观察性能采样器，记录 FPS、帧预算、平均/P95 帧耗时、长帧比例、长任务与活跃任务。
- 观察器不包含画质、像素比、粒子数量或用户设置的写入能力。
- 诊断入口：`window.__mineradioPerfSnapshot()`、`window.__mineradioPerformanceObserver.snapshot()`、`window.__mineradioVisualFrameTasks()`。
